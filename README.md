## 장보기 프로세스

1. **재고 확인:** 이미 집에 있는 식재료는 제외합니다. 선택상품 중에도 추가로 보유한 품목이 있다면 체크하여 뺍니다.
2. **구매 완료:** 실제 결제한 품목의 금액을 입력한 뒤 구매 완료 버튼을 누릅니다. 금액을 수정하거나 구매를 취소할 수 있고, 목록에 없는 추가 구매도 기록할 수 있습니다.
3. **정산:** 완료 품목, 미구매 품목, 실제 지출액과 남은 예산을 확인합니다. 기존 가계부 지출이 있다면 연결하여 중복 집계를 방지합니다.

**일요일에 다음 주 식단을 준비하는 장보기**는 다음 주(월~일)의 계획에 속하도록 처리할 수 있습니다. 가계부 탭은 실제 결제일을 기준으로 표시하므로 계획주간과 날짜별 집계주간이 달라질 수 있습니다.

## 가계부 보안과 백업

- 사용자가 입력한 실제 구매내역은 브라우저의 **localStorage**에만 저장됩니다.
- GitHub 공개 저장소에는 실제 구매 기록이 올라가지 않고 기기 간 동기화도 되지 않습니다.
- **CSV 내보내기 / JSON 백업·복원**으로 내역을 보관합니다. 브라우저 데이터를 삭제하면 기록이 사라질 수 있으니 백업을 권장합니다.
- 기존 기록의 로컬 저장소 키(`meal_real_expenses_v1`)는 유지합니다.

## GitHub Pages 최초 설정

저장소의 [Settings → Pages](https://github.com/hyogiman/Meal/settings/pages)에서 **Deploy from a branch**, `main`, `/(root)`를 선택해 저장하면 https://hyogiman.github.io/Meal/ 에서 볼 수 있습니다.

식단과 가격, UI 수정을 요청할 때마다 기존 `main/index.html`을 갱신하고 동일 URL을 유지합니다.
