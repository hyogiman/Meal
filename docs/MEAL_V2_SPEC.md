# Meal v2 — 식재료·예산 기반 가족 상차림 AI 앱 제품 명세

작성: 2026-11-01 · 상태: **차기 버전 설계안 (현재 구현된 기능과 구분)**

## 0. 제품 원칙

- 식단의 최소 단위는 **개별 주찬 하나가 아닌 한 끼 상차림**이다.
- 상차림은 주식(밥/면), 국/찌개, 주찬, 부찬(1~2개), 필요시 과일·음료로 구성한다. 가벼운 아침, 면 요리는 합리적으로 예외를 허용한다.
- 가족이 실제로 자주 먹는 한국 가정식을 기본값으로 사용한다. 익숙한 김치찌개·된장국·만둣국·계란국·제육볶음·생선구이·나물·무침 등 우선.
- 식단 추천은 **확인된 보유 재고와 실제 상품/가격**에서 시작한다. 확인되지 않은 판매가격을 AI가 지어내지 않는다.
- 맛이나 메뉴가 마음에 들지 않으면 **전체 식단 또는 특정 한 끼·반찬만 재추천**할 수 있어야 한다.
- 영양정보는 추정과 확정값을 구분한다. 브랜드 영양성분표/식품 DB/재료량이 검증되지 않으면 정밀한 수치로 표시하지 않는다.
- 재고·구매·실제 조리를 서로 다른 이벤트로 관리하여 자동으로 재고를 잘못 차감하지 않는다.
- 아기 이유식 등 다른 식단 유형은 현재 2인 성인 식비 예산과 명시적으로 분리한다.

## 1. 권장 화면 IA

- **홈/이번 주:** 예산·실제 지출·재고 우선소진·이번 주 확정 식단·다음 행동 1개
- **우리 집 재고:** 재료명/수량/단위/유통기한(미확인 허용)/보관 장소/확인일/출처
- **장보기:** 구매 예정(상품명·중량·사진 표시가·유효시각) -> 실제 결제 확정(영수증) -> 재고 반영
- **식단:** 주간 상차림 보드 (요일 x 아침/점심/저녁), 각 카드에 주식/국/주찬/부찬/과일·음료, 인분, 예상 kcal/탄단지 및 레시피
- **가계부/리포트:** 월·주 목표, 실제금액과 예상금액 분리, 품목군별 지출, 기간별 비교

## 2. AI 사진 입력 흐름

1. 냉장고·재고·식재료 사진 또는 쿠팡 장바구니 스크린샷 여러 장 업로드
2. 이미지 인식은 **후보 품목·중량·보이는 금액·수량·상품 규격·신뢰 수준**만 추출 (확실하지 않으면 null)
3. 사용자가 각 후보를 확인·수정·제외 후 저장
4. 사진에 표시된 장바구니 가격은 `observed_display_price`로만 저장. 결제완료 또는 확인된 영수증 내역만 `actual_paid`에 기록
5. 동일 품목의 중복 사진·중복 장바구니 행은 사용자가 확인하여 합치기
6. 이미지 업로드/AI 분석 실패 시 수동 입력 기능 유지

## 3. AI 상차림 생성/변경

### 요청 조건

- 구성원/끼니/주간 시작일/조리 가능 시간
- 확정된 재고(+ 단위와 수량), 기초양념, 구매 예정/확정 목록
- 주간 **남은 예산** (실제 결제액만 예산에서 차감)
- 싫어하는 음식·알레르기·익숙한 메뉴 우선 등급
- 남은 식재료 소진 기한, 재료 중복사용, 일주일 다양성, 영양 추정 정확도

### 출력 데이터

각 `meal`: `meal_id`, `date`, `slot`, `servings`, `familiarity_score`, `courses`, `nutrition`, `inventory_usage`, `extra_shopping`, `flags`.

각 `course`:
- `role`: staple | soup | main | side | fruit_or_drink
- `dish_name` / `recipe_id` / `servings`
- `ingredients`: 재료별 g/ml/개, 사용 출처(보유/구매 예정/추가필요)
- `seasoning`: **계량스푼 단위 포함 정확한 양념 배합**
- `steps`: 전처리 -> 불 세기/시간 -> 조리 순서 -> 완성 확인
- `timing`, `storage`, `leftover_plan`

**교체 UX:**
- 카드에서 `이 한 끼 바꾸기`, `주찬만 바꾸기`, `반찬만 바꾸기`
- 원하지 않는 메뉴 또는 제약(더 빠르게/덜 맵게/재료 추가 없이)을 선택하면 새 후보 2~3개 제공
- 현재 확정된 다른 끼니는 잠금(lock), 재고 사용량과 주간 총예산 재계산
- 교체 전후 영양·필요재료·추가지출을 나란히 비교한 뒤 사용자 확정
- 새 메뉴가 추가 구매를 요구하면 가격 미확인 상태로 별도 표시; 사용자 승인 전 예산에서 실결제 금액 차감 금지
- 과거 거절 메뉴와 좋아요/즐겨찾기는 향후 추천 취향에 반영

## 4. 열량·영양소 계산 규칙

**2025 한국인 영양소 섭취기준(성인 일반 범위):** 탄수화물 열량비 50~65%, 단백질 10~20%, 지방 15~30%. 이는 주로 하루·장기 식사의 균형을 위한 참고 범위이며, 식사마다 강제할 숫자는 아니다.

영양 성분 출처 우선순위:
1. 사용자가 확인한 개별 제품의 표시 영양성분 + 총 내용량/실제 사용량
2. [식품안전나라 식품영양성분 DB](https://www.foodsafetykorea.go.kr/) 또는 [USDA FoodData Central](https://fdc.nal.usda.gov/)에서 영양 데이터·레코드 ID가 확인된 표준 식품
3. 출처를 아직 매핑하지 못하면 **추정** 또는 **미확인**으로 표시 (AI가 정밀 수치를 상상해 채우지 않음)

계산:
- 식용부 무게(g) × (100g당 성분) / 100을 재료별 합산
- 식용유·설탕·양념·밥/면·음료·반찬까지 **상차림 전체 포함**
- 완성분량과 1인 실제 섭취량이 다르면 별도 조정
- 영양 환산 근사: kcal = 탄수화물(g)×4 + 단백질(g)×4 + 지방(g)×9 (섬유질, 알코올 등 미반영으로 표기 kcal와 차이 가능)
- **탄단지 열량비:** 각 영양소의 kcal / 전체 계산 kcal × 100
- 알 수 없는 양념이나 제품 수치는 무리하게 확정하지 않고 **보수적 오차 안내**
- 나트륨·식이섬유·당류는 신뢰할 만한 데이터가 있을 때 단계적으로 추가

**중요:** 탄단지 비율이 좋아도 전체 열량이 지나치게 낮으면 균형식이 아니다. 두 성인의 나이·활동량·체중·목표·식사량을 개별 설정하고, 권장 열량과 실제 메뉴량 차이를 보여준다. 기준값을 임의로 개인에게 강요하지 않는다.

## 5. 주말 다음 주 추천

- MVP: 토·일에 앱 홈에 자동으로 **다음 주 준비 카드**를 노출한다 (별도 스케줄러 없이 앱 방문 시 로컬 시간 기준)
- 카드에 `이번 주 남은 식재료 점검`, `다음 주 소비해야 할 재료`, `추천 구매 식재료 5~10개`, `예산안`, `다음 주 상차림 생성` 표시
- 사용자가 후보 식재료를 승인/제외하고 사진을 추가해 식단 생성
- 나중에 알림 기능은 명시적 동의·알림 설정·발송 빈도 제한을 적용한 뒤 Cloud Scheduler 등으로 확대
- 다음 주 시작은 현지 KST 월요일; 일요일 구매는 **다음 주 식단 계획**에 연결 가능하지만 가계부 실제 결제일은 일요일로 유지

## 6. Firebase 설계

- 별도 Meal Firebase 프로젝트 권장 (기존 앱의 데이터와 격리)
- Authentication (가족 2인), Firestore, Storage(업로드 이미지, 보존기간 설정), Cloud Functions(이미지·식단 AI 호출)
- Firestore 예시: `households/{hid}/members`, `inventory`, `shoppingLists/{week}`, `purchases`, `mealPlans/{week}`, `recipePreferences`, `settings`, `inventoryEvents`
- 기존 브라우저 `meal_real_expenses_v1`과 `meal_shopping_flow_v1`을 1회 이전하되 **원본 백업·중복 방지·검증 후 확정** 절차
- Firestore 보안규칙: 인증된 household 구성원만 해당 household 조회/수정 가능
- OpenAI 비밀키는 앱 소스/브라우저에 노출하지 않고 Functions secret으로 보관
- 호출 횟수/이미지 장수·해상도/출력 크기 제한, 비용 상한과 로그, App Check, 이미지 최소 보존, 사용자 삭제 기능
- **AI 함수**는 제품 재고나 가격의 사실 원본이 될 수 없음. 사진 분석 결과는 검토 대기 상태로 유지

## 7. 개발 단계

**1차**: Firebase 로그인/재고/예산/주간 장보기 + 기존 데이터 이전 + 상차림 UI와 조리법의 상세 계량 + 검증 가능한 영양 DB 구조

**2차**: 사진 분석 → 사람이 확인하는 상품/재고 입력, 상차림 제안, 특정 메뉴·반찬 부분 재추천, 영양/예산 교체 전후 비교

**3차**: 주말 자동 준비 카드, 가족별 식사량 조정, 재고 소비 이벤트, 실제 음식·재료별 소비와 식비 낭비 리포트, 알림 선택 기능

현재 공개 `index.html`은 Firebase/OpenAI API가 연결된 버전이 아니며, 영양 추정은 내장된 일반 식품 참고 성분과 1인분 가정으로 만든 프로토타입입니다. API 연동 및 검증된 데이터 기반 영양 계산은 차기 단계에서 구현해야 합니다.
